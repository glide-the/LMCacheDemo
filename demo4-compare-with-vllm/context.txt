 

# 大模型评测工具调研报告

本报告围绕主流大模型厂商、云平台、评测框架及专用评估工具，梳理各平台在评测流程、功能优劣、交互方式、可视化能力和可借鉴特性方面的表现，供后续系统设计与平台选型参考。

## 引言

大语言模型（LLM）的性能评估是LLM系统开发与应用中的关键环节。由于LLM输出的多样性和不确定性，传统的准确率、F1等指标已无法全面衡量模型质量。通过系统的评估，我们才能了解模型在不同任务上的强项与弱点，比较不同模型或版本的优劣，并确保模型在事实准确性、上下文连贯性和安全性等方面满足需求。完善的评估流程有助于发现模型幻觉、偏见等问题，指导后续的模型改进和迭代。这使得在LLM开发生命周期的各个阶段——从模型选择、提示词优化到模型微调和部署——都离不开评估的支持。

## 1. OpenAI评测体系

OpenAI 提供了开源的评估框架 **OpenAI Evals**，用于评测大型语言模型及其衍生应用。该框架既服务于社区，也融入了OpenAI企业级产品。OpenAI Evals 已内置一系列评测基准（如真值问答、代码生成等），用户可以通过编写JSON或Python类定制自己的评测任务，并使用OpenAI API运行评测。评测指标上，Evals支持**精确匹配**、**评分模型对比**等多种模板，甚至可以让GPT-4充当“裁判”检查自己的回答。例如，OpenAI发现GPT-4可以用于评判回答的正确性并打分，从而实现**模型自评**。在评估流程方面，开发者获取OpenAI API密钥后即可使用命令行运行评测，也可以直接在OpenAI的Web仪表盘中配置并执行评测。评测完成后，框架会生成详细报告，包含逐样本结果和汇总统计。

OpenAI 非常注重社区共建评测基准的机制。开发者认为有价值的新评测可以通过Pull Request提交到官方Evals基准库，OpenAI团队会积极审核这些贡献，以用于改进下一代模型。OpenAI 提供了贡献模板和指南，例如要求提供一定数量的示例、清晰的问题描述和评价标准等。当社区提交的新评测被接受后，就会纳入官方基准，供所有用户和OpenAI内部使用。这种共建机制极大丰富了评测集，覆盖数学推理、编码错误识别、事实准确性等各类任务，也帮助OpenAI发现GPT-4等模型的薄弱环节。据报道，一些企业用户也采用了OpenAI Evals来评估其定制应用，例如Stripe使用Evals结合人工评审来衡量其GPT驱动的文档工具的准确率。总体而言，OpenAI Evals为社区和企业提供了统一的评估框架和标准指标，并通过开源共建不断扩展评测能力。

##### 方案定位

为了保障大语言模型（LLM）在实际应用中输出内容的可靠性与一致性，评估机制（Evals）被广泛应用于模型测试与验证环节。评估的核心目标是验证模型生成的内容是否符合预期的风格与语义标准，特别适用于模型版本升级或新模型试用场景。评估不仅是模型性能调优的手段，也是构建高可靠性 LLM 应用系统的基础环节。

OpenAI 提供了灵活的评估框架，包括 API 方式和可视化仪表板配置方式。其中，API 配置方式适合在自动化流程和定制开发中集成使用。

完整的评估流程通常包括以下三个步骤：

1. **任务描述**：将待验证的功能定义为评估任务，明确模型应完成的目标行为。
2. **运行评估**：使用一组输入测试数据（包括提示词与上下文输入）运行模型，并获取输出结果。
3. **结果分析与迭代**：对模型输出进行分析，判断其符合度，进而改进提示或模型策略。

该流程理念与“行为驱动开发（BDD）”相似：先定义预期行为，再以测试驱动模型性能迭代优化。通过这样的机制，开发者可以构建出更稳定、可控、具备行为一致性的 LLM 应用系统。

## 2. 云厂商评测工具

### 2.1 Google Vertex AI — Gen AI Evaluation Service

Google Cloud 的 **生成式AI评估服务（Gen AI Evaluation Service）** 是Vertex AI平台推出的评估工具集，为用户评测任意生成式模型或应用提供了全面支持。该服务涵盖多维度的评估能力，包括提示工程优化、RAG方案优选、翻译质量、智能体(agent)任务完成情况、多语言支持等方面，几乎覆盖了当前LLM应用的主要场景。评估服务被设计为Vertex AI工作流的组成部分，用户可以通过Vertex的Python SDK或控制台UI来配置评测任务，并将评估纳入模型开发流程中。

**评估维度方面**，Google的服务非常丰富。在模型开发早期，评估工具有助于**模型选型**：提供不同预训练模型在特定数据上的基准表现，帮助用户选择最适合任务的模型。对于已选定的模型，开发者可以利用评估服务来调试**生成参数**（如温度、Top-k等），通过系统比较不同参数下输出质量来找到最佳配置。在提示工程阶段，评估服务支持对不同提示词模板的效果进行打分，帮助优化Prompt设计，引导模型输出更符合预期。如果采用**检索增强生成（RAG）\**架构，评估工具可以比较不同检索+生成流程的效果，例如不同向量数据库或检索文档数量对最终答案正确率的影响。对于翻译等任务，评估服务提供了专门的翻译质量评估（当前为预览版）。此外，当用户构建了基于LLM的复杂\**Agent**（例如多工具链调用的智能体）时，Google评估服务能衡量智能体在完成复杂任务时的能力，包括**最终答案的成功率**以及**决策轨迹的合理性**。这一点对于开发多步骤推理或带工具使用的Agent非常重要，评估既看最终结果是否达成目标，也检查中间步骤是否按预期执行。

**指标和方法上**，Google提供了**传统指标**与**模型判别式评估**相结合的方案。在摘要、翻译这类任务中，服务内置了**ROUGE、BLEU**等通用指标来衡量生成文本与参考答案之间的重合度。同时，针对语言生成的复杂质量属性（如连贯性、一致性、 factual correctness），评估服务支持使用**裁判模型（judge/autorater）\**进行打分。这个裁判模型可以是Google自家的大模型（如经过专门指令微调用于评估的PaLM模型），通过比较模型输出和参考答案，给出诸如“内容是否连贯”“事实是否准确”的评分。这种模型辅助评估使得可以定量分析那些客观指标难以度量的质量维度，弥补了ROUGE等指标只看表面匹配的不足。此外，评估服务既支持\**逐条输出的点评(pointwise)**，也支持**成对比较(pairwise)**。后者允许比较两种不同模型或Prompt对同一道题的输出，由裁判模型判断哪个更好，用于A/B测试模型或Prompt方案。

**集成工具与使用**方面，开发者可以通过Vertex AI提供的评估API和SDK构建自定义的评测管道。例如定义一个`EvalTask`，指定评估数据集和应用的指标；然后运行该任务，系统会产出评估的`Experiment`，其中包含完整的实验配置和指标结果。Vertex AI控制台也提供了初步的可视化界面：在**Vertex AI Studio**的“Freeform -> Compare”功能中，用户能交互式地选定若干提示和模型进行对比，并直观查看不同模型输出和参考答案的差异。当提供了参考答案时，UI还能计算ROUGE等分数以供参考。不过对于大批量、反复迭代的评测，还是需要借助编程方式批量化地运行。评估服务的API支持与用户的机器学习流水线集成，比如结合Google Cloud Pipeline或自定义脚本，在每次模型更新时自动调用评估服务，记录指标变化，起到类似CI的质量关卡作用。评估的结果和过程数据都托管在Vertex AI中，企业可以利用Google云的权限和日志体系确保评测数据安全。

**限制与注意事项**：Google的评估服务目前属于**Pre-GA（正式发布前）\**状态。根据Google的说明，Pre-GA功能可能在支持上有限制，且不提供正式SLA保障。因此目前应主要用于测试评估目的，而非生产关键环节。随着服务成熟，这些限制预计会逐步解除。另外，使用Google评估服务需要在Google Cloud平台上操作，有一定的使用成本（按评估请求量计费）和门槛，对于未使用Google云的团队而言适用性有限。但对于已经采用Vertex AI进行LLM开发的用户来说，这套评估工具无疑提供了与其基础设施深度融合的便利。综合而言，Google Gen AI Evaluation Service以\**全面的评估维度**和**灵活的指标方式**见长，特别适合需要在Vertex生态内对模型进行系统对比和改进的应用场景。

- **地址**：[GoogleCloudPlatform/generative-ai](https://github.com/GoogleCloudPlatform/generative-ai)
- **评测流程**：
  1. 设定业务指标
  2. 上传定制数据集
  3. 执行评测任务
  4. 可视化分析结果
- **交互方式**：Colab + Vertex SDK
- **优点**：
  - 全生命周期支持：调参、RAG、Agent、多语言翻译
  - 成对对比与逐点评估双模支持
- **缺点**：
  - 无图形操作界面，非开发用户不友好
- **借鉴意义**：
  - RAG与Agent能力评估模板设计值得引入

**核心功能与应用场景**
 Gen AI Evaluation Service 支持用户自定义评估标准，围绕生成式 AI 模型的全生命周期（包括模型选择、提示工程、微调、RAG优化等）提供系统化评估支持：

- **模型选择**：基于具体业务数据选择最佳模型，而非仅依赖排行榜或第三方报告。
- **生成设置优化**：调整如温度等参数，以优化生成质量。
- **提示工程**：支持设计和评估高质量 prompt 模板，提升模型响应准确性。
- **微调评估**：帮助确认自定义微调是否提升性能，并辅助规避偏差与失控行为。
- **RAG架构评估**：支持评估检索增强生成（Retrieval-Augmented Generation）在具体任务中的有效性。
- **模型迁移与升级**：辅助在模型替换或升级过程中评估新旧模型的表现差异。
- **翻译质量评估（预览）**：对多语言输出场景提供辅助评估能力。
- **Agent能力评估**：适用于评估多轮交互式智能体性能。

**评估流程**

1. **定义评估指标**：可设定业务相关的打分标准，支持逐点评估与成对对比评估。
2. **准备评估数据集**：数据集应贴合具体业务场景，增强评估的相关性与实用性。
3. **运行评估任务（EvalTask）**：支持模板化或从零构建，便于评估流程复用。
4. **分析评估结果**：支持可视化与量化分析，包括统计与推理性输出。
5. **高级功能（可选）**：
   - 评估判分模型本身的合理性。
   - 通过系统指令和配置优化评估一致性与抗偏差能力。
   - 针对多轮交互 agent 进行行为能力评估。

### 2.2 Azure AI Foundry

作为微软Azure OpenAI服务的一部分，**Azure OpenAI Evaluation** 提供了面向企业的评估工具，方便用户在Azure平台上对模型进行全面测试和质量度量。该评估服务目前处于预览阶段（Preview），已在部分区域开放（如East US2、North Central US等）。平台集成方面，Azure的评估功能深度融合在Azure OpenAI工作流中，支持对**各种部署类型**的模型进行评测，包括标准部署、全球多区域部署等。这意味着企业在Azure上训练或托管的基础模型、微调模型，都可以直接通过Evaluation API进行一致的评估，而无需将数据迁移出平台。

Azure Evaluation 主打**企业级模型生命周期**支持能力，贯穿模型的选择、微调、上线各环节。具体来说，在模型微调前，用户可以利用评估工具对比多个基础模型在自有数据集上的表现，从而选择最合适的基模型（模型选型阶段）。在微调过程中以及完成后，评估功能可以衡量微调带来的性能提升或退化，帮助验证微调效果是否达到预期。评估结果也可用于**模型版本管理**：当OpenAI或Azure推出新版本模型时，企业可先用评估工具跑一遍关键任务，看新模型在准确率、可靠性等指标上有无改进，再决定是否升级模型版本。微软将这一系列过程称为企业LLM的“性能保障生命周期”，评估是其中不可或缺的一环。

在评估流程和指标标准上，Azure提供了类似OpenAI Evals的**输入-输出对照测试**机制。用户需准备一个**标注了期望输出的测试数据集**（JSONL格式）上传至Azure。Evaluation服务会逐条将输入送入模型，收集模型输出，并与期望输出进行比较，计算关键指标。**准确率(Accuracy)** 是最基础的指标，适用于分类选择类任务。对于自由文本生成任务，Azure评估还关注输出的**可靠性**和**稳健性**等品质。例如，可以检查模型输出JSON格式的正确率，或多次回答的一致性来衡量稳健程度。Azure Evaluation API 支持将评测过程集成到CI/CD流水线中，开发者可以通过API脚本在每次部署前自动跑评测集，确保模型更新没有明显性能下降。此外，Azure评估还与Azure OpenAI的**日志记录**和**监控**相结合。Azure提供了“存储完成（Stored Completions）”功能来收集模型在真实业务中的问答对。这些数据可用作评测数据，从而实现**闭环的模型改进**：收集真实数据 -> 评估模型表现 -> 微调模型 -> 再评估。

区域支持方面，Azure Evaluation目前仅在部分Azure区域提供预览，但微软计划未来拓展更多区域和场景支持。对于使用Azure OpenAI服务的企业来说，该评估工具无需额外搭建，使用Azure门户或API即可一键评估模型表现，大大降低了评测门槛。同时Azure评估结果还能在Azure门户中以**可视化报告**呈现，包括各测试用例是否通过，整体准确率等，方便团队审阅。

总之，Azure OpenAI Evaluation 为企业提供了**一体化的评估方案**：借助Azure的基础设施和安全性，企业能够在本地数据合规的前提下，对LLM进行自动化、持续的性能测评和质量验证。这种平台级集成的评估工具有效支持了企业级LLM应用从开发、测试到部署运维的全生命周期管理。

### 3.1 lm-evaluation-harness

**lm-evaluation-harness** 是 EleutherAI 开发的开源LLM评测工具包，具有技术先进性和广泛的社区适用性。它预置了数十种主流基准任务的数据集和评测脚本，研究者可以轻松对语言模型进行**Few-shot评估**、**零样本评估**等。其技术优势在于**统一的接口和高度的灵活性**：支持用户根据需求配置评测选项（如上下文提示、Chain-of-Thought思维链等），并支持自定义添加新数据集或评价指标。lm-evaluation-harness 与常用数据集无缝集成，很多流行基准（如LAMBADA完形填空、HellaSwag常识推理、MMLU多学科知识测评等）都可以一键运行。评测结果包括每个任务的准确率、困惑度等指标，方便比较模型性能。

模型兼容性方面，该工具包支持**多种模型后端**。不仅支持本地的HuggingFace模型，也支持通过API调用OpenAI的GPT系列、Anthropic的Claude，以及本地轻量模型等。例如，用户可以指定`--model hf`评估本地模型，或指定`openai-chat-completions`评估ChatGPT。这种广泛的兼容性使其成为业界通用的评测利器。社区研究中，该工具广受欢迎。HuggingFace的Open LLM Leaderboard等排行榜就使用了此工具统一测评众多开源模型性能，从而确保结果的可比性。不少学术论文和开源模型报告也采用lm-evaluation-harness来复现和对比模型在标准基准上的表现。这说明该工具包经过验证非常可靠，已成为评估LLM学术研究中的事实标准之一。

评估流程上，lm-evaluation-harness 提供了命令行界面。例如运行 `python -m lm_eval --model hf --tasks triviaqa` 可以对指定模型进行TriviaQA问答数据集的评测，并输出模型的准确率等指标。用户也可通过Python API调用更细粒度地控制评估过程。综合来看，lm-evaluation-harness 以其**丰富的内置基准、灵活定制和广泛模型支持**，为研究人员和开发者提供了强大的评测工具，在社区中具有很高的声誉和适用性。

## 4. 专用评测框架 DeepEval（Confident AI）

**DeepEval** 是由初创公司Confident AI推出的开源LLM评估框架，主打CI/CD集成、对抗性测试和安全评估等应用场景。其设计理念是将LLM的评估像软件单元测试一样简单直观。开发者可以编写**测试用例**（包含输入Prompt和期望输出或判定规则），然后用DeepEval来批量执行这些测试，从而实现对LLM输出结果的自动验证。DeepEval 提供了Pytest风格的断言和报告机制，让团队在持续集成流水线中轻松加入LLM结果的验证，一旦新模型版本出现输出退化或错误，CI流程会立即报告回归情况。许多企业已将DeepEval纳入其MLOps流程，实现LLM功能的**准入测试**和**回归测试**。

在指标支持方面，DeepEval内置了**30+种评测指标**（大多有学术研究背景支撑）。这些指标涵盖了问答匹配、文本相似度、内容安全等各个方面，几乎满足不同应用对模型输出质量的评价需求。此外，DeepEval允许用户自定义指标，非常灵活。例如，针对**RAG（检索增强生成）\**场景，DeepEval内置了\**Contextual Precision/Recall**（查看检索到的文档与期望答案的匹配程度）、**答案相关性**、**忠实度**（衡量输出是否基于检索内容，无幻觉）等专门指标。又比如对于开放性的对话或生成任务，DeepEval提供**G-Eval**模块，可利用大模型作为“裁判”依据特定标准对输出打分（类似OpenAI的GPT-4评分）。同时，开发者还能方便地将**偏见、真实性、格式合规**等自定义检查加入评估管道，以满足特定业务需求。这种可插拔的指标体系保证了评估的**覆盖面和针对性**。

DeepEval在**安全评估和对抗攻击**方面也颇有特色。它提供了完善的**红队测试**（Red-Teaming）模块，内置了常见漏洞和不良行为的测试集，包括偏见、虚假信息、恶意指令（违法行为）、隐私泄露、提示词泄露等十余种安全维度。开发者可以一键运行这些攻击性测试，检验模型在极端输入下是否表现出不安全倾向，并根据结果改进模型的安全策略。例如，可以测试模型在遭遇带有种族歧视倾向的问题时，是否会输出偏见内容；或在引导下是否会泄露机密信息。DeepEval 将这些安全测试集成在框架中，生成详细的安全评估报告，有助于企业及时发现LLM应用的潜在风险。

值得一提的是，Confident AI 还提供了DeepEval的云平台（Confident AI平台）来增强协作和持续监控。通过该平台，团队可以在云端管理评估数据集、Prompt模板，查看测试报告仪表盘，并实时监控生产环境下模型输出的质量和安全指标。DeepEval与Confident AI云平台无缝集成：本地运行`deepeval`评测时，结果可自动同步到云端，便于团队共享和追踪评测历史。据官方介绍，Confident AI平台已经被世界各地众多企业采用，包括部分财富500强公司，用于**基准测试、守护模型质量和提升应用可靠性**。自开源以来，DeepEval在GitHub上已有数千星标，pip月下载量超十万，显示出良好的社区影响力。总的来说，DeepEval以**工程实用性**见长，在CI/CD流程融入、复杂指标支持和安全评估方面提供了业界领先的解决方案，非常适合对LLM应用要求高可靠性的团队使用。

- **地址**：[confident-ai/deepeval](https://github.com/confident-ai/deepeval)
- **评测流程**：
  1. 编写类Pytest的测试用例
  2. 本地运行或云端托管执行
  3. 收集指标报告与行为追踪数据

交互形式：接口交互，文件jsonl批量评估

分析形式：接口交互、官网仪表盘

DeepEval 是一个开源的大语言模型（LLM）评估框架，专为LLM输出的单元测试设计，类似于 Pytest，但聚焦于 LLM 系统的性能评测。该框架可在本地运行，集成多种先进评测指标与策略，并支持用户自定义评测流程。

适用于 LangChain、LlamaIndex 等框架下的 RAG 流水线、Agent 系统、Chatbot 应用及私有化模型部署评估。也支持从商业API迁移到本地模型（如 DeepSeek R1）时的评估验证。

涵盖通用、RAG、Agent、对话等多类评估指标，支持自定义扩展、合成数据生成，并具备 40+ 项安全攻击测试能力，可无缝集成至 CI/CD 流程，快速完成主流评测集的基准测试。

支持常见评测集如 MMLU、HellaSwag、TruthfulQA、HumanEval、GSM8K 等 



DeepEval 托管Confident AI 云平台（按量计费），可支持从评估数据集的构建、模型测试对比、指标微调、结果追踪与线上表现监控的完整闭环 、上线后用户数据驱动的持续迭代优化

  



## 5 、应用驱动的评测体系（TruLens ）

 

TruLens 将反馈函数（feedback function）视为 LLM 应用的组成单元 —— 给定输入文本返回一个评价结果。这种视角促使评估过程本身具备自动化和可重复性特征，支持对模型行为（如 GPT-3.5、GPT-4）和提示策略（如思维链）进行细致追踪与比较。用基础性、答案相关性和上下文相关性来检测幻觉。

## 总结与建议

在纷繁的评估工具生态中，选型需结合自身应用场景和技术背景。

**如果您主要使用OpenAI的模型和API**，且希望参与社区基准对标，那么**OpenAI Evals**是顺理成章的选择。它与OpenAI模型契合度高，且有大量社区提供的评测用例，能直接利用。不过需要有一定的编程基础来编写评测。而对于**关注开源模型研究**的团队，**lm-evaluation-harness**提供了标准化的评测框架，可以在本地对各类开源模型跑学术基准，保证结果具有公信力。它非常适合模型效果报告、学术论文复现等用途。

**如果您的需求侧重实际产品质量和持续交付**，**DeepEval**无疑是一个强有力的工具。它让LLM评测融入CI/CD流水线，自动化地监测模型性能变化和安全合规问题，避免了人工盲点，非常适合构建对输出要求严格的商业应用。同时配套的Confident AI云平台还能方便地管理测试数据和结果，提升团队协作效率。许多初创公司和大企业都已将DeepEval纳入开发流程以守护模型品质。

对于**已有云平台战略**的企业用户，最佳选择往往是在现有云服务中使用其评估套件：在Azure生态中开发的应用，应充分利用**Azure OpenAI Evaluation**来实现模型的全生命周期评测和管理；而构建在Google Vertex AI上的项目，则应尝试**Gen AI Evaluation Service**，以利用其强大的评估指标组合和实验追踪能力。这两者与各自云平台的其他功能（数据存储、监控告警等）无缝集成，能减少额外集成成本。不过需要注意目前这些服务尚在预览，具体功能和支持范围可能会进一步完善。
